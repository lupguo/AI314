# AI314 规划约束清单

本技能只规定"spec / plan 里必须写进什么"，不规定流程与存放位置。流程与位置沿用当前驱动的流程技能（如 brainstorming / writing-plans），本清单叠加其上。

## 1. 开工前

- 读项目根 `AGENTS.md` 的 AI314 声明块，列出本次涉及路径对应的 `ai314:stack-*` / `ai314:mode-*`，并加载它们。
- 读 `docs/base/` 下与本次相关的活文档（`PRODUCT` / `ARCH` / `UI` / `API` / `DEPLOY`），以项目现状为基线。
- 宪法第 9 条：主动提出用户未提及但必须关注的要点与能力边界；不可逆决策中断确认，可逆细节取行业默认值并标注"默认值"。
- 宪法第 7 条：确认流程、UI 布局、目录结构、架构选型等决策点时，优先产出 HTML 草稿（`docs/_drafts/` 或 `.superpowers/`）。

## 2. spec / plan 必须包含

- **每个任务**附两小节：
  - `约束`：相关宪法条款编号（如"§3 单文件 ≤300 行"、"§4 不改公开接口"、"§5 新依赖需声明理由"）及 stack/mode 的具体红线。
  - `自检命令`：取自对应 stack 第 4 节的 lint / 类型检查 / 测试命令，供完成前验证使用。
- **公开接口变更清单**（宪法第 4 条）：将改动的 API / Schema / CLI 参数逐项列出待用户确认；无则写"无"。
- **`docs/base/` 影响清单**（宪法第 8 条）：完成时需回写的文件与段落；无则写"无"。
- 新增依赖：依赖名、版本、理由、已核对的清单与锁文件（宪法第 5 条）。
- 测试策略：只覆盖主链路与关键边界（空值 / 超时 / 并发）（宪法第 13 条）。
- 重复操作：构建 / 部署 / 代码生成写成 `Makefile` 或 `scripts/` 目标（宪法第 11 条）。
- 执行方式：按 Plan 规模推荐子代理驱动或当前会话执行（宪法第 10 条）。
- 收尾：最后一个任务为"用 `ai314:docs-base-sync` 回写 `docs/base/`"（影响清单为"无"时省略）。
