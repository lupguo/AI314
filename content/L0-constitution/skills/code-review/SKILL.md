# AI314 代码审查清单

若已有其他审查技能在驱动，沿用其流程，只叠加本清单。先读项目 AI314 声明块，加载改动路径对应的 stack/mode 技能，其第 3 节红线一并检查。

| 宪法条款 | 检查点 |
| :-- | :-- |
| §3 文档即契约 | 行为/接口变化是否同步更新 `docs/` 对应 MD |
| §6 交互 | 是否未经确认新增页面/弹窗；是否复用既有 Design Token 与组件 |
| §7 复杂度 | 单文件 >300 行、单函数 >50 行、跨层调用、循环依赖 |
| §8 最小变更 | 是否修改公开 API/Schema/CLI 签名；是否夹带无关重构或全文件格式化 |
| §9 依赖 | 新增第三方依赖是否在计划中声明并核对锁文件 |
| §10 注释 | 注释是否解释 Why 而非 What；对外接口是否有签名与出入参说明 |
| §11 根因 | 是否用 try-catch/忽略错误吞异常；修复是否有复现用例 |
| §12 测试 | 是否篡改断言、硬编码返回值骗过测试；主链路与关键边界是否覆盖 |
| §13 脚本化 | 新增的重复操作是否进入 Makefile/scripts |
| §15 安全 | 是否硬编码密钥/Token；`.env*` 是否在 `.gitignore` |

## 输出格式

按严重度（Critical / Important / Minor）排序的表格：`严重度 | 文件:行 | 条款 | 问题 | 建议`。无问题时明确写"未发现问题"，并附上实际运行过的 lint/测试命令与结果（宪法第 11、14 条）。
