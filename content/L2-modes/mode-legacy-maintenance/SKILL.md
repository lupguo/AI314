# 旧系统增量维护模式补丁

## 1. 存量系统手术铁律

- **先锁行为，再动代码（Characterization Test）**：老代码往往缺少文档与测试。在修改任何核心函数前，**必须先针对现有输入输出编写“特征测试”锁定当前行为**，确保重构后原有逻辑零偏移。
- **严禁大规模格式化与顺手重构**：修改老文件时，禁止运行全文件自动格式化（避免 Git Diff 出现几百行无关空格变更干扰 Review），严格把 Diff 控制在目标逻辑周围 20 行内。
- **尊重历史技术债边界**：除非明确立项重构，否则新代码必须顺应老项目的依赖版本与既有架构风格，严禁在老项目中强行引入第二套平行框架（如在旧 Vue2 项目里混写 React）。
- **渐进式防腐层（Anti-Corruption Layer）**：若必须对接老旧脏接口，通过独立的 `Adapter` 适配器封装脏数据转换，避免污染新增的干净业务模块。
