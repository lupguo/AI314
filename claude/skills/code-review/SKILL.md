# AI314 代码审查清单

若已有其他审查技能在驱动，沿用其流程，只叠加本清单。先读项目 AI314 声明块，加载改动路径对应的 stack/mode 技能，其第 3 节红线一并检查。

| 宪法条款 | 检查点 |
| :-- | :-- |
| §1/§2 产品与交互 | 是否未经确认新增页面/弹窗；是否复用既有 Design Token 与组件 |
| §3 架构 | 用 `wc -l` 测改动文件行数（>300 即违反）；单函数 >50 行；跨层调用、循环依赖 |
| §4 最小变更 | 是否触碰公开 API/Schema/CLI（以 `docs/base/API.md` 为准，存在时）；是否夹带无关重构或全文件格式化 |
| §5 依赖 | 新增第三方依赖是否在 spec/plan 中声明并核对锁文件 |
| §6 注释 | 注释是否解释 Why 而非 What；对外接口是否有签名与出入参说明 |
| §8 文档 | spec/plan 的 `docs/base/` 影响清单是否已回写；README 文档地图是否需更新 |
| §11 脚本化 | 新增的重复操作是否进入 Makefile/scripts |
| §12 根因 | 是否用 try-catch/忽略错误吞异常；修复是否有复现用例 |
| §13 测试 | 是否篡改断言、硬编码返回值骗过测试；主链路与关键边界是否覆盖 |
| §14 安全 | 是否硬编码密钥/Token；`.env*` 是否在 `.gitignore` |
| mode | 启用 `mode-legacy-maintenance` 时，修改核心函数前是否有特征测试 |

## 严重度

- **Critical**：违反 §14；未经确认改公开接口（§4）；篡改断言或硬编码骗测试（§13）。
- **Important**：其余条款违反。
- **Minor**：注释、命名、风格类。

## 输出格式

按严重度排序的表格：`严重度 | 文件:行 | 条款 | 问题 | 建议`。无问题时明确写"未发现问题"，并附上实际运行过的 lint/测试命令与结果。
