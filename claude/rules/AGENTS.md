# AI314 工程宪法

> AI314 宪法版本：v0.3.0

## 零、 加载与优先级（最高优先级）

- **技能路由**：项目根 `AGENTS.md` 中 `<!-- AI314:BEGIN -->` ~ `<!-- AI314:END -->` 声明块按路径启用 stack / mode，改动对应路径前必须先加载对应技能（`ai314:<技能名>`）。未声明时，按文末《已挂载技能索引表》的触发条件加载。
- **优先级**：用户当次指令 > 项目 `AGENTS.md` > 已启用 `mode-*` 的豁免条款 > 本宪法 > 流程技能（如 superpowers）的默认值。**第 14 条安全底线不可豁免。**
- **与流程技能协作**：头脑风暴、计划、执行、审查的流程由流程技能驱动，本宪法只叠加约束。编写 spec / plan 时**同时加载** `ai314:planning`；审查代码或宣告完成前**同时加载** `ai314:code-review`。

## 一、 产品与交互

1. **产品设计**：遵循奥卡姆剃刀，给用户最直觉、有经验的产品体验（UI、CLI、API 皆然），规避冗长、反流程的设计。
2. **交互设计**：优先采用业界前沿通用标准（UI 设计、产品美学、交互体验、快捷键）；禁止未经确认引入新页面 / 多级弹窗，默认单屏直达；视觉与组件严格复用项目既定 Design Token / UI 库，禁止自由发挥样式。

## 二、 架构与代码

3. **架构设计**：分层 + 模块化目录；在 KISS 前提下权衡后续扩展性与可维护性，禁止过度设计（YAGNI）。**单文件不超过 300 行，单函数不超过 50 行，禁止跨层直接调用与循环依赖；超限时先拆分再继续加功能。**
4. **最小变更**：严格 Minimal Diff。未经明确指令，严禁修改现有公开接口（API / Schema / CLI 参数，以 `docs/base/API.md` 为准）的签名与字段结构，严禁顺手重构无关文件。
5. **依赖选型**：优先语言标准库与项目现有依赖；新增第三方依赖前，先核对依赖清单与锁文件（`go.mod`/`go.sum`、`package.json`/lock、`Cargo.toml`/`Cargo.lock` 等）确认兼容，并在 spec / plan 中声明理由。
6. **注释**：尽量一句话说清楚，解释 Why（业务意图 / 踩坑原因）而非 What，限 1~3 行；对外暴露的模块 / 接口保留标准类型签名与入参出参说明。

## 三、 协作与文档

7. **可视化确认**：与用户确认决策点（业务流程、产品功能、UI 布局、技术架构、项目目录、模块设计）时，优先用 Web HTML 交互，不必在意 token 用量。草稿放 `docs/_drafts/` 或 `.superpowers/`（均加入 `.gitignore`），确认后结论写入 spec。
8. **文档即契约**：
   - 特性契约：编码前的 spec / plan 由流程技能产出（如 `docs/superpowers/`）。
   - 项目活文档：`docs/base/` 下 `PRODUCT.md`（业务与产品）、`ARCH.md`（架构、目录布局、组件与技术选型）、`UI.md`（UI 选型与交互规范）、`API.md`（公开接口契约）、`DEPLOY.md`（环境、构建、发布、运维），按需创建，始终反映项目当前真实状态。
   - 特性完成、合并前用 `ai314:docs-base-sync` 增量回写受影响段落，禁止全量重写；单篇超 300 行拆为同目录 `<名>-<模块>.md`，原文件保留为索引。
   - `README.md` 只保留项目核心介绍、上手方式与文档地图。
9. **主动提示与默认值先行**：头脑风暴 / 计划阶段，主动提出用户未提及但实施中必须关注的要点，超出能力范围的事主动告知。区分"不可逆决策"与"可逆细节"：前者必须中断确认；后者直接采用行业最佳实践落地，并在交付说明中标注"已默认采用 X，如需调整请告知"。
10. **模型与执行方式**：架构设计 / 头脑风暴用高阶模型，子代理执行用常规高性价比模型；Plan 执行阶段按 Plan 规模推荐采用子代理驱动或当前会话执行。

## 四、 质量与安全

11. **脚本化**：构建、部署、测试、Proto 编译、配置替换等重复流程，优先封装为 `Makefile` / shell / python / go 命令。
12. **根因与验证闭环**：复现 → 抓证据（日志 / 报错堆栈 / 截图）→ 定位根因 → 写失败用例 → 修复 → 跑通验证。严禁盲改试错和 try-catch 吞异常掩盖错误。
13. **TDD 2/8 原则**：测试聚焦核心主链路与关键边界（空值 / 超时 / 并发）；**严禁修改断言或硬编码返回值骗过测试。**
14. **安全底线**：票据、密钥、Token 一律通过环境变量注入，`.env*` 必须加入 `.gitignore`，严禁硬编码进代码或文档。
